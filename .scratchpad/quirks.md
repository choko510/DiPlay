# Quirks — environments and workarounds

> Preserved historical observations, organized by theme. Some are host- or version-specific and may now be obsolete; verify before applying.


## Local Windows / SDK / Gradle

- Managed worktrees omit the ignored `local.properties`; setting `ANDROID_HOME` and `ANDROID_SDK_ROOT` to the installed SDK allows Gradle builds. The shared native module pins NDK 27.0.12077973. GeckoView 156 needs Android SDK platform 37.1; it was missing locally and had to be installed from Google's official repository before AAR metadata checks/builds could pass.
- In this checkout, set `ANDROID_HOME` and `ANDROID_SDK_ROOT` to `%LOCALAPPDATA%\Android\Sdk` for Gradle. The repository's `ndk.dir` emits AGP CXX5106 deprecation warnings; they are nonfatal, and the full test aggregate plus mobile/automotive debug builds pass.
- 2026-10-28 review remediation: the managed worktree process did not inherit Android SDK/JDK variables. Setting both SDK variables to `%LOCALAPPDATA%\Android\Sdk` and `JAVA_HOME` to Android Studio `jbr` enabled all 930 Shared/Common tests; the duplicate suffixed API 37.1 platform warning remained nonfatal.
- 2026-10-28: Git's configured VS Code `--wait` editor path was missing when continuing the remote-update merge. The prepared merge message completed safely with `git -c core.editor=true merge --continue`.
- 2026-10-28: Windows Git uses `core.autocrlf=true`, so pinned EX-08 JSONL/JSON files have LF in the index but CRLF in the worktree. `generate_step4_ex08_inventory.py --check` hashes raw bytes and reports a delta-111 metadata digest mismatch in this checkout; do not edit the ledger to hide it. The same run's ADB list contained only an x86_64 emulator, so API 29 physical USB attach acceptance remained `NOT_RUN_HARDWARE`.
- 2026-10-01: After rebasing onto main #9, 270 shared and 55 common Gradle tests, the full test aggregate, both debug builds, and mobile lint pass. Explicit `:shared:lintDebug` and `:common:lintDebug` still fail on existing permission/NewApi/translation issues in unchanged files (Bluetooth/Wi-Fi/P2P, AppLanguage, manifests/resources); the updated audio renderer has no lint findings.
- 2026-10-01: On Windows, the repository's Java 25 Gradle daemon could not load Robolectric's temporary `libandroid_runtime.dll` (`UnsatisfiedLinkError: access denied`). The affected test and full suite passed with installed Android Studio JBR 21 by temporarily overriding the daemon JVM version and restoring `gradle/gradle-daemon-jvm.properties` afterward.
- The 8-second startup snapshot and 15-second hard timeout reflect the slow-success timing in the 2026-09-30 brief. UIS8581/iOS 27 physical validation is still required.
- 2026-10-01: MSYS2 UCRT GCC runs `scripts/test_dsp_native.sh`, but its installation lacks `libasan` and `libubsan`; the local `--sanitize` link fails. The workflow runs the same ASan/UBSan command on Ubuntu.
- 2026-10-19: On this host `bash.exe` in PATH is the WSL launcher and fails with `HCS_E_SERVICE_NOT_AVAILABLE`; explicitly invoke `C:\msys64\usr\bin\bash.exe` for MSYS2. When launching from PowerShell, the Bash `PATH` also needs `/ucrt64/bin:/usr/bin:/bin`; `bash -lc` resets the working directory, so use `bash -c` and preserve the repository cwd. MSYS2 UCRT GCC 15.2 runs the native DSP test normally but its installation lacks `libasan`/`libubsan`, so the sanitizer link fails. Local Gradle selects NDK 27 via `ndk.dir` while app modules expect 28.2, producing CXX1104/unstripped DSP library warnings; Debug and Benchmark builds pass.
- 2026-10-19: Robolectric `ParcelFileDescriptor.createSocketPair()`/`fromSocket()` did not provide a reliable full-duplex TUN fixture for both bridge workers on this Windows host. Keep the production PFD path intact and use the bridge's internal stream hooks with a piped input and scripted output for deterministic TUN-write, peer-MAC and OUT-result tests.

## Hosted CI / emulator

- 2026-10-02: `reactivecircus/android-emulator-runner` runs `script:` lines as separate shell invocations. Put multi-step test, logcat capture, and evidence assertions in a checked-in bash script and invoke it with a single command; capture before the action shuts down the emulator.

MSYS2 UCRT GCC can run `scripts/test_dsp_native.sh` but lacks `libasan`/`libubsan`; the NDK Clang x86_64 suite passed on the API 36 emulator with `ASAN_OPTIONS=detect_leaks=0` and `UBSAN_OPTIONS=halt_on_error=1`. SDK warns about a duplicate API 37.1 platform and an incomplete NDK 28.2 folder; selected NDK 27 builds and tests pass.
- 2026-10-09: `:shared:testDebugUnitTest` had one unrelated IPv6 loopback failure (`SocketException: Permission denied: connect`) in `AirPlayIapTunnelStreamTest`; the targeted NCM profile tests pass. The ADB list showed only `emulator-5554` offline; connecting to `192.168.1.28:9876` timed out.
- 2026-10-01: The Android SDK setup action installed emulator packages without adding the emulator binary to PATH, and `avdmanager` remained interactive in GitHub Actions. Use `reactivecircus/android-emulator-runner` to create, boot, and tear down the x86_64 AVD for connected tests.
- 2026-10-02: The SDK repository advertised emulator build `16428233`, but its archive URL returned 404; build `16433917` was reachable. Install that archive directly with `unzip -o` to replace runner-provided emulator files, and pass an AVD device profile to `avdmanager` to avoid the interactive hardware-profile prompt.
- 2026-10-02: Hosted `avdmanager` and `emulator` did not resolve the same AVD home by default. Set and export `ANDROID_AVD_HOME` explicitly, then verify the AVD ini exists before launching the emulator.
- 2026-10-02: The GitHub Ubuntu runner's `/dev/kvm` was not accessible to the emulator. Apply the standard udev rule and trigger before launching x86_64 tests so the emulator action can use hardware acceleration.
- 2026-10-02: The hosted Ubuntu runner has no accessible `/dev/kvm`; x86_64 emulator startup fails unless hardware acceleration is disabled. The managed emulator action checks KVM and selects `-accel off` when needed.
- 2026-10-02: On Windows Robolectric, `AtomicFile.finishWrite()` uses a rename operation that does not replace an existing profile file; this caused the schema-v1/v2 migration tests' persisted-schema assertions to read the old file. The tests now inject a direct writer for those migration-only cases. Production Android persistence still uses `AtomicFile`. MSYS2 UCRT GCC lacks host `libasan`/`libubsan`, so `scripts/test_dsp_native.sh --sanitize` cannot link there. The same native test source was cross-compiled with NDK ASan/UBSan and passed on the x86_64 API 36.1 emulator with LeakSanitizer disabled.
- 2026-10-28: The Windows Robolectric preset-delete runtime test also injects a deterministic workspace writer to avoid the known `AtomicFile.finishWrite()` replacement limitation; Android API 35 instrumentation tests the real atomic rollback path.
- 2026-10-21: The local Android Emulator 36.4.9.0 refused a second process using the existing AVD name even with a separate `datadir`; a distinct temporary AVD config was required. This emulator rejects `-no-sdcard`. The U74 test AVD is left registered but powered off after uninstalling the test package; recursive removal outside the workspace was blocked by shell policy, and `avdmanager` is not installed here.
- 2026-10-23: The local `Medium_Phone_API_36.1` AVD was accidentally launched with `-wipe-data` during p99 reproduction; this reset that emulator's userdata. It was powered off afterward; no physical iPhone or head unit was touched.
- 2026-10-22: On this Windows host, unfiltered `:common:testDebugUnitTest` runs ended with Gradle `EOFException` or a missing `in-progress-results-generic.bin`, while the focused `CarPlayHostActivityLocalScaleTest` passed 2/2. Use focused test-class runs for local iteration and confirm the full common suite in the hosted lane; do not treat the incomplete local run as a full-suite pass.
