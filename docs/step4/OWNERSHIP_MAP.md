# STEP4 source ownership map

Source anchors below are from fixed main `95ba398f95ee104527812cd2b095977d71c51f98`. A stage changes only the owner it needs and preserves the adjacent fallback.

| Area | Main owner | Responsibility and boundary |
|---|---|---|
| USB / NCM | `shared/src/main/java/com/shilapi/xcertplay/transport/IphoneUsbHost.kt`; `NcmFunctionDiscovery.kt`; `NcmUsbBridge.kt`; `Ntb16Codec.kt`; `PersistentUsbReadRequestState.kt` | USBMUX/iAP2 owns its persistent request; NCM owns its connection, endpoint selection, bulk-IN queue/wait, NTB framing, and OUT result. Do not combine requestWait owners or change behavior during EX-01. |
| NCM → TUN → TCP | `shared/src/main/java/com/shilapi/xcertplay/network/Ipv6NcmBridge.kt`; `CarPlayVpnService.kt` | `Ipv6NcmBridge` moves IPv6 frames to/from TUN and NCM. `CarPlayVpnService` owns VPN FD, listener generation, accept loop, and attachment-scoped sockets. Packet proof, TUN write, and socket accept remain separate milestones. |
| Wired startup / recovery | `shared/src/main/java/com/shilapi/xcertplay/orchestration/CarPlayController.kt`; `WiredStartupWatchdog.kt` | `CarPlayController.openDataPaths()` owns wired startup attempt/recovery and the existing 8 s soft / 15 s hard watchdog. Preserve one retry owner, token and attachment generations. |
| AirPlay control and display protocol | `shared/src/main/java/com/shilapi/xcertplay/airplay/AirPlayConfig.kt`; `AirPlayInfoPlist.kt`; `AirPlaySession.kt` | Immutable display capabilities and initial `/info` serialization live separately from authenticated AirPlay command delivery/handling. Sending a command is not evidence that an iPhone accepted it. |
| Host UI / Split | `common/src/main/java/com/shilapi/xcertplay/CarPlayHostActivity.kt` (including nested `CarPlayBackgroundSession`); `common/src/main/java/com/shilapi/xcertplay/youtube/SplitLayoutState.kt`; `DisplayResizeCoordinator.kt`; `YoutubeDeviceProfile.kt` and adjacent YouTube/profile classes | Activity owns pane layout, display-size callbacks, touch routing, restart fallback, and visible Gecko session. The retained background owner and YouTube profile storage remain identity-scoped. Local scaling must not mutate remote dimensions or transfer controller ownership. |
| Media / Surface | `shared/src/main/java/com/shilapi/xcertplay/media/AndroidMediaSink.kt`; nested `VideoDecoder`; `CarPlayTouchMapper.kt` | Media sink owns decoder and output surface lifecycle; touch mapping uses declared display dimensions. Surface/codec changes stay separate from controller/network restart policy. |
| Audio / microphone | `shared/src/main/java/com/shilapi/xcertplay/airplay/CarPlayMediaEngine.kt`; `AndroidMediaSink.kt` nested `AudioRenderer`; `AudioRendererLifecycle.kt`; `MicrophoneUplink.kt` | Stream classification, output renderer, microphone request/lifecycle and RTP are distinct owners. `input=false` remains a hard capture veto; non-MEDIA roles retain existing DSP policy. |
| DSP configuration and persistence | `common/src/main/java/com/shilapi/xcertplay/dsp/DspProfileRepository.kt`; `DspProfileRuntime.kt`; `DspSettingsActivity.kt` | Common owns persisted profile schema, migration and UI configuration. Unknown future schema must not be overwritten. |
| DSP runtime / native graph | `shared/src/main/java/com/shilapi/xcertplay/media/dsp/DspPcmPipeline.kt`; `NativeDspProcessor.kt`; `shared/src/main/jni/dsp/dsp_graph.c`; `dsp_engine.c` | Shared owns conversion, prepared processor lifecycle and JNI. Native graph owns real-time processing. Prepare allocations off-thread; preserve master-off PCM path and MEDIA-only full processing. |
| Diagnostic export | `shared/src/main/java/com/shilapi/xcertplay/orchestration/ConnectionTraceEvent.kt`; `common/src/main/java/com/shilapi/xcertplay/ConnectionTraceStore.kt`; `DiagnosticRedactor.kt` | Structured event schema, bounded storage and redaction are separate. EX-01 must not put packet payload, raw IP/MAC, credentials or pairing data into exports. |

## PR-00 additions

`shared/src/test/java/com/shilapi/xcertplay/step4/` owns deterministic test inputs and transport fakes only. It does not replace production USB, TUN, audio, video or UI owners. `docs/step4/` records the baseline, test status, ownership boundaries, upstream decisions and feature defaults.
